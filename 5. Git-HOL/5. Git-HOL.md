## 1. Theoretical Concepts: Cleaning Up & Pushing to Remote Git

### Workspace Clean Up in Git
During development, the working directory often gets populated with temporary files, build artifacts, or experimental code. Managing these changes is essential before pulling or pushing code to ensure conflict-free merges.

Key Git cleanup commands:
1. **`git status`**: The primary inspection tool. It lists:
   - Tracked files that have been modified.
   - Untracked files that are not ignored.
   - Staged files ready to be committed.
2. **`git restore <file>`** (or `git checkout -- <file>`): Discards local modifications in the working directory for tracked files, resetting them to their last committed state.
3. **`git clean`**: Used to delete untracked files from the working directory.
   - `git clean -n`: Dry run to show which files will be deleted.
   - `git clean -f`: Forces the deletion of untracked files.
   - `git clean -fd`: Forces the deletion of both untracked files and directories.
4. **`git stash`**: Temporarily shelves (stashes) your current modifications (both staged and unstaged) to restore a clean working directory, allowing you to switch branches or perform pulls without committing unfinished work. Stashed changes can be reapplied later using `git stash pop`.

### Remote Synchronization (Pulling & Pushing)
1. **`git pull <remote> <branch>`**: Fetches changes from the remote repository and immediately attempts to merge them into the local active branch. It is a combination of `git fetch` and `git merge`.
2. **`git push <remote> <branch>`**: Uploads local commit history to the remote repository branch, making your local changes available to other collaborators.
