## 1. Theoretical Concepts: Branching & Merging

In version control systems, branching and merging are core concepts that enable concurrent development, experimentation, and clean release management.

### Branching
A **branch** in Git is a lightweight, movable pointer to a specific commit. By default, Git starts with a main branch (historically called `master` or `trunk`). 
* **Isolated Environment:** Creating a branch creates a copy of the pointer, allowing you to edit files, commit changes, and test new features without affecting the stable `master`/`main` codebase.
* **Parallel Workflows:** Teams can work on multiple features, bug fixes, or experimental code simultaneously.

### Merging
**Merging** is the process of combining the history and changes from one branch back into another (typically merging a feature branch back into the main trunk).
* **Fast-Forward Merge:** If the destination branch has no new commits since the source branch was created, Git simply moves the pointer forward to the commit at the tip of the source branch.
* **Three-Way Merge:** If both the destination and source branches have progressed independently, Git locates a common ancestor commit and performs a three-way merge, creating a new merge commit.

## 2. Collaborative Workflows: GitLab & GitHub

In modern development teams, changes are rarely merged directly on local machines without review. Instead, platforms like GitLab and GitHub provide formal review pipelines.

### Creating a Branch Request (GitLab/GitHub)
A **branch request** (or creating a branch on a remote server) occurs when you push a local branch to the remote repository.
1. **Via command line:**
   ```bash
   git push -u origin GitNewBranch
   ```
2. **Via UI:** In the GitLab/GitHub interface, you can navigate to the **Branches** section and click **New Branch**, specifying its name and source (e.g., `main`).

### Creating a Merge Request (GitLab) / Pull Request (GitHub)
Once changes are committed and pushed to a remote branch, developers open a request to merge those changes into the main trunk.
* **GitLab (Merge Request - MR):**
  1. Navigate to the project page on GitLab.
  2. Click **Merge Requests** in the left sidebar, then click **New merge request**.
  3. Select the source branch (`GitNewBranch`) and target branch (`main`).
  4. Write a title and description detailing what changes are included, assign reviewers, and click **Submit merge request**.
* **GitHub (Pull Request - PR):**
  1. Navigate to your repository on GitHub.
  2. GitHub will often show a banner: *"GitNewBranch had recent pushes... Compare & pull request"*. Click that button.
  3. Select source and target branches, write description details, and click **Create pull request**.

*Reviewers can then inspect code differences, leave comments, run automated testing (CI/CD), and eventually click **Merge** to integrate the branch into the trunk.*

## 3. Visual Diffing & Merging: P4Merge Configuration

Git allows you to integrate visual GUI tools for diffing and resolving conflicts. **P4Merge** by Perforce is a popular tool for this.

### Setting Up P4Merge on Windows

1. Download and install the **Perforce Visual Merge Tool (P4Merge)** from the official Perforce website.
2. The default installation path is usually:
   * `C:\Program Files\Perforce\p4merge.exe`
3. Configure Git globally to use P4Merge as the default diff tool:
   ```bash
   git config --global diff.tool p4merge
   git config --global difftool.p4merge.path "C:/Program Files/Perforce/p4merge.exe"
   ```
4. Configure Git globally to use P4Merge as the default merge resolution tool:
   ```bash
   git config --global merge.tool p4merge
   git config --global mergetool.p4merge.path "C:/Program Files/Perforce/p4merge.exe"
   ```
5. When configured, running `git difftool main..GitNewBranch` will launch the P4Merge GUI, displaying the differences side-by-side.

## 4. Hands-on Lab: Local Branching Steps

Here is the step-by-step execution of the local branching tasks.

### 1. Create a New Branch `GitNewBranch`
Create the branch pointer locally.
* **Command:**
  ```bash
  git branch GitNewBranch
  ```

### 2. List All Local and Remote Branches
Inspect branches and identify the current active branch (indicated by `*`).
* **Command:**
  ```bash
  git branch -a
  ```
* **Actual Output:**
  ```text
    GitNewBranch
  * main
    remotes/origin/HEAD -> origin/main
    remotes/origin/main
  ```
  *(Observation: The `*` indicates that the workspace is currently pointing to `main`.)*

### 3. Switch to the Newly Created Branch and Add Files
Switch active branch and create `3. Git-HOL/sample.txt` with testing content.
* **Command to Switch:**
  ```bash
  git checkout GitNewBranch
  ```
* **Actual Output:**
  ```text
  Switched to branch 'GitNewBranch'
  ```
* **Action (Create File):** A file `3. Git-HOL/sample.txt` was created with the following content:
  ```text
  This is a sample file created on GitNewBranch to demonstrate branching and merging in Git.
  Adding some contents to track.
  ```

### 4. Stage and Commit Changes to the Branch
Add the file to the staging area and commit it.
* **Commands:**
  ```bash
  git add "3. Git-HOL/sample.txt"
  git commit -m "Add sample file on GitNewBranch"
  ```
* **Actual Output:**
  ```text
  [GitNewBranch db560cb] Add sample file on GitNewBranch
   1 file changed, 2 insertions(+)
   create mode 100644 3. Git-HOL/sample.txt
  ```

### 5. Check Status
Verify the working status of the branch.
* **Command:**
  ```bash
  git status
  ```
* **Actual Output:**
  ```text
  On branch GitNewBranch
  nothing to commit, working tree clean
  ```

## 5. Hands-on Lab: Local Merging Steps

Here is the step-by-step execution of the local merging and cleanup tasks.

### 1. Switch Back to the Trunk (`main`)
* **Command:**
  ```bash
  git checkout main
  ```
* **Actual Output:**
  ```text
  Switched to branch 'main'
  Your branch is up to date with 'origin/main'.
  ```

### 2. List Out Differences via Command Line Interface
Examine what differs between the trunk and the feature branch.
* **Command:**
  ```bash
  git diff main..GitNewBranch
  ```
* **Actual Output:**
  ```diff
  diff --git a/3. Git-HOL/sample.txt b/3. Git-HOL/sample.txt
  new file mode 100644
  index 0000000..f0e245e
  --- /dev/null
  +++ b/3. Git-HOL/sample.txt
  @@ -0,0 +1,2 @@
  +This is a sample file created on GitNewBranch to demonstrate branching and merging in Git.
  +Adding some contents to track.
  ```

### 3. List Visual Differences Using P4Merge
To view diffs visually, run the difftool command (requires P4Merge configured as in Section 3):
* **Command:**
  ```bash
  git difftool main..GitNewBranch
  ```

### 4. Merge the Source Branch to the Trunk
Integrate the changes from `GitNewBranch` into `main`.
* **Command:**
  ```bash
  git merge GitNewBranch
  ```
* **Actual Output:**
  ```text
  Updating 0817c49..db560cb
  Fast-forward
   3. Git-HOL/sample.txt | 2 ++
   1 file changed, 2 insertions(+)
   create mode 100644 3. Git-HOL/sample.txt
  ```

### 5. Observe Logging After Merging
Inspect the commit graph to see branch integration.
* **Command:**
  ```bash
  git log --oneline --graph --decorate -n 5
  ```
* **Actual Output:**
  ```text
  * db560cb (HEAD -> main) Add sample file on GitNewBranch
  * 0817c49 (origin/main, origin/HEAD) 2.Git-HOL
  * f2b9234 1.Git-HOL
  * 2bc951d ReactJS-HOL-13
  * e70378a ReactJS-HOL-12
  ```

### 6. Delete the Branch After Merging and Verify Status
Delete the local pointer since the changes are safely integrated into the trunk.
* **Command to Delete:**
  ```bash
  git branch -d GitNewBranch
  ```
* **Actual Output:**
  ```text
  Deleted branch GitNewBranch (was db560cb).
  ```
* **Command to Verify:**
  ```bash
  git branch -a
  ```
* **Actual Output:**
  ```text
  * main
    remotes/origin/HEAD -> origin/main
    remotes/origin/main
  ```
  *(Observation: `GitNewBranch` has been successfully cleaned up, leaving a clean workspace.)*
