This document contains the step-by-step implementation of the Git Hands-on Lab based on the provided instructions.

## Step 1: Setup Machine with Git Configuration

### 1. Check Git Client Installation
Verify if Git is installed properly on the system.
* **Command:**
  ```bash
  git version
  ```
* **Expected Output:**
  ```text
  git version 2.21.0.windows.1 (or higher)
  ```

### 2. Configure Global User Identity
Configure the user level global user ID and email ID. Replace `NainaVerma` and `nainaverma@gmail.com` with your credentials if different.
* **Commands:**
  ```bash
  git config --global user.name "NainaVerma"
  git config --global user.email "nainaverma@gmail.com"
  ```

### 3. Verify Configurations
Check if the configurations are set correctly.
* **Command:**
  ```bash
  git config --global --list
  ```
* **Expected Output:**
  ```text
  user.name=NainaVerma
  user.email=nainaverma@gmail.com
  ```

## Step 2: Integrate Notepad++ with Git as Default Editor

### 1. Check Notepad++ Command in Git Bash
Test if `notepad++` can be executed directly from Git Bash.
* **Command:**
  ```bash
  notepad++
  ```
* **Note:** If it returns `bash: notepad++: command not found`, follow the steps below to add it to the system Path environment variable.

### 2. Add Notepad++ to Path Environment Variable
If Notepad++ is not recognized, add its installation path to the environment variables:
1. Open **Control Panel** -> **System** -> **Advanced System Settings**.
2. Go to the **Advanced** tab and click **Environment Variables**.
3. Under **User variables**, select **Path** and click **Edit**.
4. Click **New** and add the Notepad++ installation path (typically `C:\Program Files\Notepad++`).
5. Click **OK** to save and exit.
6. Restart Git Bash and verify by typing:
   ```bash
   notepad++
   ```

### 3. Create a Git Bash Alias for Notepad++
Create a shortcut command `npp` for Notepad++ in your bash profile.
* **Command to edit profile:**
  ```bash
  notepad++ ~/.bash_profile
  ```
* **Line to append in the file:**
  ```bash
  alias npp='notepad++.exe -multiInst -nosession'
  ```

### 4. Configure Notepad++ as Git's Default Editor
Configure Git to use Notepad++ when prompting for commit messages.
* **Command:**
  ```bash
  git config --global core.editor "notepad++.exe -multiInst -nosession"
  ```
  *(Alternative if path is not set: `git config --global core.editor "'C:/Program Files/Notepad++/notepad++.exe' -multiInst -nosession"`)*

### 5. Verify Editor Integration
Open the global Git configuration file in the default editor.
* **Command:**
  ```bash
  git config --global -e
  ```
* **Expected Behavior:** Notepad++ should open and display the global git configuration:
  ```ini
  [user]
      name = NainaVerma
      email = nainaverma@gmail.com
  [core]
      editor = notepad++.exe -multiInst -nosession
  ```

## Step 3: Local Repository Actions & File Management

### 1. Initialize a Local Repository "GitDemo"
Create and initialize the local git repository directory.
* **Command:**
  ```bash
  git init GitDemo
  ```
* **Expected Output:**
  ```text
  Initialized empty Git repository in C:/Users/naina/OneDrive/Desktop/DeekSkilling/1. Git-HOL/GitDemo/.git/
  ```

### 2. Verify Directory Initialization
Verify that the repository is initialized by listing all files including hidden ones.
* **Command:**
  ```bash
  ls -al
  ```
* **Expected Output:**
  ```text
  drwxr-xr-x 1 username 1049089 0 Jan 13 11:54 ./
  drwxr-xr-x 1 username 1049089 0 Jan 13 11:54 ../
  drwxr-xr-x 1 username 1049089 0 Jan 13 11:54 .git/
  ```

### 3. Create a File "welcome.txt" and Add Content
Create the file and write initial text into it.
* **Command:**
  ```bash
  echo "Welcome to the version control" >> welcome.txt
  ```

### 4. Verify File Creation
List the directory contents to confirm the file exists.
* **Command:**
  ```bash
  ls -al
  ```

### 5. Verify Content of the File
Print the contents of `welcome.txt` to the terminal.
* **Command:**
  ```bash
  cat welcome.txt
  ```
* **Expected Output:**
  ```text
  Welcome to the version control
  ```

### 6. Check Repository Status
Check the status of the repository to see untracked files.
* **Command:**
  ```bash
  git status
  ```
* **Expected Output:**
  ```text
  On branch master

  No commits yet

  Untracked files:
    (use "git add <file>..." to include in what will be committed)

          welcome.txt

  nothing added to commit but untracked files present (use "git add" to track)
  ```

### 7. Add File to Staging Area
Add `welcome.txt` to track it in Git.
* **Command:**
  ```bash
  git add welcome.txt
  ```

### 8. Commit Changes Using Default Editor
Commit the staged file. This will open Notepad++ where you can write a multi-line commit message. Save and close Notepad++ to finalize the commit.
* **Command:**
  ```bash
  git commit
  ```

### 9. Verify Post-Commit Status
Check status to ensure the working tree is clean.
* **Command:**
  ```bash
  git status
  ```
* **Expected Output:**
  ```text
  On branch master
  nothing to commit, working tree clean
  ```

## Step 4: GitLab Remote Repository Integration

### 1. Create a Remote Repository
* **Action:** Sign up/Login to GitLab and create a new project.
* **Project Name:** `GitDemo`
* **Visibility Level:** Private / Public (as preferred)

### 2. Link Local Repository to Remote GitLab
Add the GitLab repository as a remote origin for your local repository.
* **Command:**
  ```bash
  git remote add origin https://gitlab.com/your-username/GitDemo.git
  ```

### 3. Pull from Remote GitLab
Retrieve and merge changes from the remote repository's `master` branch.
* **Command:**
  ```bash
  git pull origin master
  ```

### 4. Push Local Repository to Remote GitLab
Push the local `master` branch commits to the remote GitLab repository.
* **Command:**
  ```bash
  git push origin master
  ```
